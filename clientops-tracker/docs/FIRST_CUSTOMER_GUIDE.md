# First Customer Guide

Candidate guidance, not a claim that the current published images contain it.
In the working portal, reopen **Start here** from navigation. The fictional public
walkthrough is separate and cannot create accounts, tickets or decisions.

## Administrator: Set Up One Client

1. Sign in with the privately bootstrapped administrator. Open Start here. Create
   a client in Clients, then select **Client to set up**. The URL remembers that
   selection, including when returning with the browser Back button.
2. Choose Create project. Confirm the preselected client and create its project.
   Project created feedback confirms persistence. Return using Back to this client's setup.
3. Choose Invite client contact. Confirm Role = Client and the organisation, enter
   the intended contact, then Send invitation. Check Email delivery in Accounts.
   Queued is not sent; Accepted by mail server is not proof of inbox delivery.
4. The contact opens their own invitation and sets their password. Only then does
   an active eligible reviewer appear. Do not sign in as them or record their decision.
   If the invitation expires, resend it from Accounts. Investigate failed mail first.
5. Let the client create a ticket, or record their request from your own staff account.
   The setup checklist links to the real request and first client decision when present.
   An outcome agreement or request for changes counts as a decision, **not acceptance**.

The older **Installation setup** checklist remains an installation-wide overview.
It is not evidence that any single client completed onboarding. The selected-client
guide never uses a different client's project, account, request or decision.

## Developer: Deliver for Review

Open My work in Needs attention, or Start here -> Open my work. Read Request,
Scope change and Delivery and acceptance before implementation. Scope approval,
outcome agreement, ticket resolution and delivery acceptance are separate facts.

- For a feature request, Propose scope change records scope, exclusions, estimate
  and implications. Request scope approval names the authorised client approver.
- Propose outcome records acceptance criteria, owner and optional target. Request
  outcome agreement requires an active contact from this ticket's organisation.
  An invited but inactive person is not eligible. The client acts next.
- After Outcome agreed, choose Delivered in release from the same project, add
  Delivery notes for the client and Request acceptance. Ask an administrator to
  create the release if none exists; developers cannot create releases.
- Changes requested leaves feedback and history intact. Propose revised outcome
  requires fresh agreement before another acceptance request. A new scope revision
  likewise requires a new scope decision.
- Before commenting, choose Reply to client or Internal note. The matching send
  button identifies the audience. Delivery notes are always client-visible.

## Client: Request and Decide

Create ticket asks for a project, title and description. If no project exists,
the agency administrator must create one; the form explains this before entry.
After submission the saved ticket opens. My decisions shows decisions assigned to
you; the organisation's delivery plan includes broader permitted information.

Follow a review email, sign in if needed, and arrive at its record and section.
Read the current revision and comparison, then the release and delivery evidence.
Choose Accept delivered work or Request changes with feedback and save. The named
reviewer alone sees decision controls. A different contact sees who acts next.
The saved decision persists after refresh and sign-in. A shipped release does not
automatically resolve the ticket or mean you accepted it.

## Common Questions

- **Find work:** Tickets supports search and filters; Delivery plan lists current
  decisions and commitments. A proposed target is not an agreed deadline.
- **Summaries:** staff preview drafts before publishing. Clients see only their
  organisation's publications. These are immutable dated snapshots; linked records
  show the current state, which can differ from the briefing.
- **Export:** on a ticket, Delivery and acceptance -> Export client delivery record.
  This text record excludes internal comments/triage. Review it before sharing.
- **Recovery:** Sign in -> Forgot password. The response is deliberately generic.
  Check inbox/spam, request a fresh expired reset link, or ask an administrator to
  resend an expired invitation. Changing a password ends existing sessions.
- **Errors:** a failed save is not success. Read the error and retry/load the current
  record; do not assume an old revision can still be decided. Unavailable/other-client
  records return no business content. Account access may have been revoked.
